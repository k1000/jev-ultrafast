Purpose

Declare one objective, immutable caller-owned final checks, and optional prepared milestones/text. Reuse the current Jev decision loop and single-shot browser boundary. Success is a fresh verified outcome, never a model signal or execution acknowledgment.

Caller policy data → validated envelope → ObjectiveAgent
    fresh observation → Jev operation + observed target → Browser.execute
    fresh caller verification → next decision or stop

Constraints and existing evidence

  • Check, Text, Step, Plan and parse_plan already supply data-only predicates, bindings, and milestones.
  • action_space and choose already construct operation-specific target heads from observed elements in one TypeSafe request.
  • ObjectiveAgent already owns fresh verification, bounded correction, and default zero runtime replans.
  • Browser.execute already validates unique observed actions, checks freshness, records before input, and locks after uncertain execution.

Do not replace these with YAML expressions, user-selected handlers, a second state machine, or multi-operation adapters such as submit_login.

Closed v1 envelope

Exactly four required keys. version is integer 1 (not boolean). objective is a nonempty, at-most-2,000-character string with no leading/trailing whitespace; reject rather than silently rewrite it. checks is a nonempty array of existing Check records. prepared_plan is either null or an existing closed {objective, plan} record with an exactly matching objective.

{
  "version": 1,
  "objective": "Set Memo to Reviewed, submit, and verify Complete.",
  "checks": [
    {"kind": "value", "label": "Memo", "value": "Reviewed"},
    {"kind": "text", "value": "Complete"}
  ],
  "prepared_plan": {
    "objective": "Set Memo to Reviewed, submit, and verify Complete.",
    "plan": [{
      "goal": "Complete the requested memo flow",
      "texts": [{"label": "Memo", "value": "Reviewed"}],
      "checks": [{"kind": "text", "value": "Complete"}]
    }]
  }
}

This is public offline-fixture data, not a hardcoded executor value or a site-specific action sequence. The same envelope can express other caller objectives without changing the executor.

  • Reuse Check kinds: url, url_contains, title, text, value, checked. Reuse existing binding/length/type rules; optional control disambiguation is role/group.
  • Reject extra keys at every object boundary, unsupported versions, malformed types, changed objectives, selector/code/capability execution fields, and final-check overrides. Do not dispatch arbitrary functions or evaluate expressions.
  • Copy accepted input before execution. Final checks remain caller-owned and independent of plan checks. A planner may supply only the existing plan contract, never this caller envelope.
  • A supplied plan makes zero planner calls by default; null permits at most one logical upfront planner invocation, and none if the initial outcome is already verified. Existing HTTP-helper retries do not become extra controller planner invocations; this is not a paid-request count. Jev still selects runtime actions. V1 sets max_replans=0; existing explicit replanning APIs remain separate.

Outside the policy: initial URL, API credentials/endpoints, browser/session handles, safety callbacks, model configuration, and execution budgets are trusted caller/server settings. Keep existing defaults: 24 decisions/actions, 90 seconds, two corrections per stable blocker, five-second outcome settling. Callers may lower limits or apply stricter trusted safety validation; the policy cannot raise them or authorize consequential actions.

Decision, execution, and state semantics

BoundaryContract
ObservationOne fresh snapshot supplies page facts, actionable elements, and final-check evidence. Missing, obscured, ambiguous, or unreadable facts are unknown, not success. Replace current facts on each observation; never merge stale facts into current proof.
MemoryKeep bounded recent actions, current preferred milestone, verified/deferred progress, and stable-blocker budgets separately. Historical progress is advisory and cannot authorize an input or prove a final outcome.
DecisionFixed vocabulary: CLICK, TYPE_TEXT, SELECT, SCROLL_TO, SCROLL_UP, SCROLL_DOWN, WAIT, DONE, BLOCKED. Offer only supported observed choices plus terminal signals. Jev selects an operation and its operation-specific target; consume only that target head. Preserve current response validation, including membership and probability checks.
ResolutionTarget indexes are observation-local references, never CSS selectors or callable names. Bind TYPE_TEXT only to a uniquely observed field with prepared text. SELECT uses an observed option. No model-generated text, coordinates, URLs, or code.
AuthorizationThe existing pre-input validation boundary must still accept the action and supplied text. Deployment-specific safety policy is trusted server code. A model confidence threshold is not authorization, and a policy cannot approve a purchase, submission, deletion, or message.
ExecutionOne logical observed operation per decision, issued once. It may require multiple CDP messages; “atomic” does not mean transactional or exactly-once network delivery. SCROLL_TO only reveals; any subsequent interaction needs another observation and decision.
Receiptexecuted means acknowledgment, not goal success. rejected_before_input permits bounded read-only settling and a fresh decision, never replay. outcome_unknown stops input and preserves inspection access; neither a model retry judgment nor a later successful check unlocks the instance.
CompletionAll caller checks must be freshly met on the same snapshot, together with any trusted additional verifier. DONE remains advisory; BLOCKED is not proof of impossibility. Loading waits and configured settling are read-only and cannot replay mutations.
TraceReuse the redacted evaluation export. Count acknowledged actions from the attempt ledger separately from rejected/uncertain attempts. Inconclusive/incomplete outcomes keep a null score and remain in the verified-rate denominator.

The observation/history interface is POMDP-style. This design does not prove Markov sufficiency, train a policy, introduce reward learning, or treat calibrated probabilities as deterministic safety evidence.

Implementation surface

  • jev_ultrafast/policy.py: parse_policy() returns a frozen Policy containing existing immutable Check/Plan records. agent_kwargs() returns defensive controller arguments with max_replans=0. No new runtime or registry.
  • tests/test_policy_contract.py: 65 offline boundary/composition cases, with HTTP/CDP transport blocked.
  • examples/objective.py: a policy-file entry path that converts validated data into existing ObjectiveAgent arguments before browser setup. Preserve legacy flags as a separate path; reject mixing policy-owned goal/check/plan fields with competing CLI flags.
  • Existing controller, decision model, executor, and reporter: reuse, not replace.

Acceptance assertions

  • Malformed or conflicting policy data causes zero browser setup, zero model calls, and zero inputs.
  • A supplied prepared plan and zero runtime replans yield zero planner/helper calls; a missing prepared value cannot synthesize text or invoke a runtime planner.
  • Jev cannot execute an unoffered operation/target or consume another operation's target head.
  • An unmet/unknown final check cannot be overridden by a milestone, DONE, cached progress, or acknowledgment.
  • Pre-input staleness requires a fresh decision; uncertain input issues no further mutation and remains inconclusive with inspection access retained.
  • Redacted reports retain categories/counters only; uncertain scroll attempts do not inflate confirmed action counts.

Baseline: 388 offline tests passed before this contract. Implementation: 453 offline tests now pass, including 65 policy cases. Risks, limits, and rollback

  • No confidentiality guarantee: current model context includes viewport text, ordinary field values, prepared text, and recent typed values. Password inputs are not offered, but other page content may still be sensitive. V1 is restricted to reviewed non-secret tasks; it provides no secret references, credential filling, redaction classifier, or login capability. A caller must not place secrets in policy data or expose sensitive pages. Supporting secrets requires a separately designed model-projection boundary.
  • Weak predicates: a caller can choose a check already satisfied initially. This is a caller acceptance-design problem, not something the planner should repair or relax.
  • Process-local safety: uncertain-input locking is not durable crash recovery or browser-side exactly-once delivery. Do not resume or recreate a run automatically.
  • Scope: no YAML, expression evaluator, configurable transition graph, capability names, plugins, browser handles, secret store, arbitrary navigation, multi-action macros, or new Noul/Score calls.
  • Rollback: remove the parser and policy-entry path; the existing ObjectiveAgent API and caller-owned checks remain the fallback. Do not modify or rewrite historical evidence.

Notes and decisions

No blocking design questions. Assumptions: public reviewed task data, browser-only v1, existing fixed operations, trusted caller checks, and reuse of current local safety semantics. These are scope restrictions, not claims that a secret detector or new runtime is present.

Optional later work, not part of this contract: stronger confidential model-state projection, other environment adapters, or declarative subpolicy composition. Add these only for a demonstrated requirement, with their own deterministic tests.
